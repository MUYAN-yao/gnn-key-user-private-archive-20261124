# v7 候选遗漏检查：分阶段实验设计

日期：2026-09-19；版本0.1。

状态：实验设计已完成，尚未冻结为正式预注册，未启动网络实验或训练。
数学规则见 `v7_partial_world_bound_method_note.md`，配置见
`v7_omission_check_design_v0_1.json`，逐项运行表见
`v7_omission_check_planned_matrix_v0_1.csv`。运行表全部为planned_not_run。

## 1. 研究问题与贡献边界

RQ1：能否在不提前知道完整搜索答案的条件下，保守排除不会成为当前
贪心胜者的候选，避免固定候选截断漏掉重要节点？

RQ2：计入上界构造、检查与扩展成本后，这种做法是否比完整扫描更省计算？

RQ3：初始候选池与风险项上界，是否分别优于普通分支定界和不含风险项的界？

本轮优先研发算法机制，GNN不进入核心矩阵。主实验无需模型训练。
原有v6结果只作发现材料；所有已看过的Digg/Higgs网络都归开发用途。
方法若正确，完整搜索与精确剪枝同解是应满足的性质，而不是新的质量增益。
发表价值需来自与已有方法的实质区别、实际效率和失效条件，不能只靠同解。

## 2. 待检验的方法

固定W个选择世界。每轮先完整评估排名靠前的2k个未选节点得到当前最好值，
然后检查其余全部节点的合法得分上界。无法排除的候选每批补4个世界；
能排除则停止该候选，不能排除则评估到W。全部候选处理后提交本轮胜者。

上界利用未观察世界的最大可能传播量，以及已观察结果给出的总体标准差
下界。它不要求目标次模。上界的数学证明和数值实现规则见方法备忘。
“池外抽查没有异常”及“连续两次扩容同解”都不被当作正确性证书。

## 3. 三个必须先过的启动关卡

G0 贡献检查：逐项比对GCOMB的预算相关阈值、UBLF的传播量上界、
EXPGREEDY/TOPX的自适应采样，以及H-DeepPruner的候选集构造。
当前基础上界和分支定界不是已确认的新颖成果。若只有对标准剪枝的重新命名，
不进入正式大实验。原文来源与核对范围见本文件末尾。

G1 正确性：数值比较、结构界、缓存键、逐轮选择全部验证通过。
任何错误剪枝或与规范full轨迹不一致，都必须修复并重新验证后再进入性能实验。

G2 可行性：开发集必须出现能覆盖检查开销的节省，并能说明收益来源。
若所有开发条件都不优于FULL，或普通分支定界解释了全部收益，停止当前
候选扩展主张。可记录通用剪枝结果，但不能把它当作新方法已成功。

这些是科学与实现条件，不是重新向用户请求批准。常规开发在既有授权内进行。

## 4. 公共计算协议

| 项目 | 主设计 |
| --- | --- |
| 种子预算k | 5、20 |
| 扩散模拟 | 有向IC，h=4，沿用可复核的step-indexed随机试验语义 |
| 概率模型 | 所有有效边p=0.05；声明为模拟设定，不是学习出的真实概率 |
| 决策目标 | 均值 - 0.35×总体标准差 + 0.25×种子社区数 |
| 主选择世界W | 20；另设W=80次要实验 |
| 独立评估世界E | 1000，所有方法共享，完全不用于选节点、扩容或调参 |
| 默认排序 | 历史加权出度，按节点字符串ID破排序同分 |
| 初始池 | min(2k,剩余节点数) |
| 补评估批量 | 4个世界；最后不足4个时补完剩余世界 |
| 目标破同分 | 数学目标半偶舍入六位后，按节点字符串ID；所有臂一致 |
| 缓存 | 各臂冷缓存，合法相同集合/world缓存；拓扑缓存256 MiB |

参数是本次方案的工程选择，不是证明充分的精度或期刊录用标准。
实际传播、风险偏好与社区公平不作为本研究的新应用结论。

### 图与社区构造

按排序后的唯一时间戳组取前65%（floor，至少一组），包含完整边界时间组。
仅使用此截点前出现的端点为节点集，去自环并记录数量；有向重复边聚合，
权重为保留事件数。保留所有分量和孤立于传播方向的节点，不挑最大有利分量。
无历史边或节点数少于k的实例标为不适用，不能换截点找更好结果。

社区从当前图的无向投影得到，双向边权相加，按规范节点/边顺序构造，
使用固定版本NetworkX的greedy modularity，保存社区映射及哈希。
不使用未来事件、级联标签、GNN特征或测试阶段信息。
这仍只是历史快照上的模拟优化，不宣称真实的未来传播预测。

此v7协议的图构造、概率及数值计算独立成版，不能与v6数值拼接或冒称重放。

### 世界与随机性

世界ID由版本、图哈希、概率哈希、种子、family、index的SHA256确定，
截取63位后检查无重复；selection与evaluation分离。
同一图、种子、概率下跨k共享世界，故不同k是相关条件。
W80实验的前20个世界与W20相同，按重复测量敏感性解释。
各臂顺序在运行前固定随机化，并写入冻结manifest；不能按预计快慢或结果换序。

## 5. 对照方法

| ID | 方法 | 关键问题 |
| --- | --- | --- |
| full | 全节点×全部选择世界的完整贪心 | 规范参考和计算成本 |
| fixed_2k | 出度排序前2k个候选 | 小候选池的质量损失 |
| fixed_6k | 出度排序前6k个候选 | 对应较宽候选范围 |
| fixed_12k | 出度排序前12k个候选 | 固定池质量—成本曲线 |
| doubling | 从2k开始倍增，连续两次有序种子相同则停，否则直到全图 | 简单自适应是否已经足够 |
| generic_bound | 无初始池，按最大上界优先的普通分支定界，同一SSE界 | 扩展调度是否超出通用剪枝 |
| check_mean_bound | 与拟议算法一致，上界不减SSE项 | 风险信息是否有独立作用 |
| check_risk_bound | 初始池+结构界+部分世界SSE界 | 设计候选，不预设优越 |
| gcomb_degree_component | 按GCOMB思路重实现预算相关出度阈值模块 | 与已发表筛选思路比较 |

固定池大小均截断到n。doubling每次在扩大后的全局排名前缀上重新运行
规范贪心，可使用合法的相同集合缓存；其同解停止是启发式，不提供证书。

GCOMB模块对每个k，用开发集全部full解的最差出度排名/n的最大值作为
阈值tau_k，新图取ceil(n*tau_k)，截断到[k,n]。不使用新图full答案，
不在两个已设预算间额外插值。明确称“组件重实现”，不冒充完整GCN+Q-learning
GCOMB，也不据此宣称超过完整GCOMB或当前最优算法。实现需对照原文审核。

执行依赖：先完成全部E2 full，再一次性拟合tau_k并保存，最后运行该组件；
它在E2的表现属于样本内开发结果。E3只用冻结阈值，按预定臂顺序运行。
另外记录该模块所需的完整贪心标注生成和阈值拟合成本；单次查询应计入这项
必需离线成本，重复查询另给Q=10、100的固定摊销核算，不能免费预训练。

主效率比较：check_risk_bound对generic_bound及check_mean_bound；
对full作参考。只有比full快而不比强对照好，不足以支持新增机制的贡献。

## 6. 顺序实验矩阵

### E0：数学规则检查，已完成的设计验证

已检查395,505个小向量/前缀/lambda组合，未发现界失效。
这不涉及网络、训练或实际加速，不能算一批论文性能实验。

### E1：微型图正确性，下一步实施

六种固定fixture：有向链、出星、断开分量、重复邻域、靠后排名的互补节点、
完全/近似同分。每图最多8节点，W=8，h取1和4；lambda取0、0.35、1，
eta取0和0.25。枚举长度至多3的合法前缀及候选，检查每个r处上界。
同时运行k=1..min(4,n)逐轮full对照，验证所有精确臂。

增加等概率0/1、负目标、半微单位边界、缓存重用/清空、节点字符串排序、
r=0/r=W以及内存/时间中止的专项用例。结构界不能小于实际世界传播。
通过条件是零错误剪枝、零错误证书和零精确轨迹差异。

### E2：开发可行性实验，不训练GNN

本地 `data/processed/digg/pilot-5000` 和
`data/processed/higgs-twitter/pilot-1500`，文件名数字是输入规模标识，
不冒充实际图节点数；构图后报告真实n,m。

2网络×2预算×3种子（101、102、103）=12配对块；9方法=108次方法执行。
所有选择世界W=20、评估世界E=1000。固定同一套参数，不做大网格搜索。
另在此开发层做B=n对照，记录结构界构造时间、松紧程度及剪枝发生的r/W。
其成本也记入开发阶段限额。

在E2结束时评估：是否有错误；是否节省候选—世界调用；总耗时是否节省；
收益来自SSE、排序/调度、缓存还是普通剪枝；困难案例怎样退化。
若需要改方法，另存设计0.2，开发结果标为探索性；不得带着改动直接续接正式版本。

### E3：新网络核心验证，条件性计划

候选来源为CollegeMsg和email-Eu-core-temporal，各取上述65%历史快照。
它们均是通信网络：两个数据集不能代表任意网络，邮件/消息边也不是传播父子真值。
必须先记录使用条件、来源链、字段语义、原始及处理文件哈希才可准入。
本轮没有下载，也没有把候选来源标为已获许可或已准入。

2网络×k={5,20}×5种子（201—205）=20配对块；9方法=180次方法执行。
这是有限条件性能验证，不是20个独立网络或事先证明了统计功效的样本量。
相同规范种子集合在每块只做一次独立评估，所有臂引用同一结果哈希。

### E4：选择世界预算敏感性，预先列入资源预算

两新网络、k=20、同5种子，W从20增加到80。
只运行full、generic_bound、check_mean_bound、check_risk_bound：
10块、40次方法执行。检验加速是否依赖特别小的选择世界数。
这不是增加独立网络，也不据其重复结果翻倍样本量。

核心与敏感性合计30配对块、220次方法执行；开发层另108次。
所有这些是逐项可追踪的计划，当前执行数为零。

## 7. 评价与统计

### 硬正确性门槛

每个完成块的精确臂须逐轮与v7 full有相同winner、有序种子及规范目标。
任一不一致都暂停该版本，不以最终均值相近或不显著掩盖错误。
同解导致独立世界效用相等是实现检查，不包装成统计等效或新质量发现。

### 时间与工作量

分别记录共同准备T_common（加载、构图、概率、社区）、每臂T_decision
（排序、结构界、数值比较、检查、扩展、缓存管理和搜索）及离线评估T_eval。
共同准备每块独立计时，按T_cold_accounted=T_common+T_decision报告单次
总成本核算值；同时给出T_decision，明确前者为组件相加而非逐臂重跑原始输入。
不得隐藏上界预计算。若以后训练GNN，训练/校准/推断均必须加入相应成本。
需要离线拟合的组件，单次T_cold_accounted还须加必需标注生成/拟合成本，
同时分列该一次性成本；主比较的三个精确剪枝臂没有这项学习成本。

唯一主效率口径为T_cold_accounted比值，分别对两个强对照；full作参考。
T_decision比值和工作量是解释性次指标，不能替换不利的主指标。
另列模拟候选—世界调用、边试验、完整评估比例、promotion、峰值内存、
构界耗时与最长实例。每臂使用新进程或等价清空状态，统一线程，计时串行。
开发阶段做计时重复检查噪声，但不把重复计时算新的科学样本。

### 近似方法质量

fixed/doubling/GCOMB组件与full在同一E世界上比较Delta J、均值传播、
标准差及社区数；报告相同解/不同解和质量—成本曲线。所有臂都必须用当前
规范目标评价。未设有应用依据的非劣界，不以任意1%或p>0.05声称等效。

### 统计单位

每个network×k展示全部5个配对点、均值/样本SD、中位数、范围和完成率。
主要结论为条件性描述，不为小样本强加不可靠的显著性或网络总体置信区间。
可报告每块配对Delta J和时间比；不把E=1000个世界或k/窗口当作独立网络。
核心不设正式p值检验或多重挑选最佳对照；不依据观察结果追加种子求显著。

## 8. 资源限额与失败处理

开发阶段总墙钟上限6小时；E3+E4合计上限72小时；单方法上限3600秒；
单块上限18000秒；进程内存上限8 GiB。正式实现需用外部watchdog中止，
不能等方法返回后才检查。单次检查、准备及离线评估都计入阶段墙钟。

新网络预检仅在方法冻结后运行full、独立种子190，不用于方法调参。
记录图规模、准备时间、full时间和内存；筛选结果/效用不向开发环节展示。
对k5/W20、k20/W20和k20/W80分别预检，覆盖全部计划难度。

保守估算：C_dev为开发中完成方法相对full决策时间比的最大值，至少1；
L=1+ceil(log2(max(1,n/(2k))))上界倍增级数。E3每块按
1.5*C_dev*(8+L)*T_full，E4每块按1.5*C_dev*4*T_full估算，另加准备与评估。
这是带余量的启动估计，不是最坏运行时间证明。总量超过72小时则不启动
该正式版本，公开记录可行性失败，在读取正式方法效果前整体修订方案。

若开发中任何正式保留臂仍有未解决的超时、内存或数值失败，仅由完成行算出
的有限C_dev不足以放行。先修复或整体另立版本，并保留失败。删失时间是
下界，不得当作该方法的保守耗时上界。组件必需的离线拟合成本另加一次，
不隐去，也不在每次实际执行的墙钟投影中重复充算。

超时或内存失败保留T>=上限、原因、部分轨迹和未获证书状态。
某臂缺失的块不计算完整时间比；报告所有计划块完成率，不能只挑成功完成的
块声称加速。正式过程中要改算法、k、世界数或阈值，结束该版、保存原记录，
另立版本；受结果影响的数据转入开发用途。

## 10. 投稿判断规则

正确但不快：记录可行性失败，停止效率主张。
比full快但不优于通用剪枝：机制创新仍未成立。
只在开发网络好：不能给泛化结论。
只有学习排序增加成本而无收益：不把GNN作为必要模块。
若方法有明确区别、实现正确、独立条件下总成本收益稳定且边界可解释，
再重评Applied Intelligence。没有任何一个固定加速倍数等同录用门槛。
